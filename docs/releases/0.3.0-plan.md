## Release checks

- Every CI step passes: `./gradlew clean buildPlugin check` and `./gradlew verifyPlugin` on 2025.1 and the latest release, with no new internal, experimental or deprecated API use. The [2026-11-08 record](../VALIDATION.md#2026-11-08-030-release-checks) lists the results and compares the verifier usages with 0.2.0.
- Relationship matching changed, so [RELEASING.md](../RELEASING.md) step 3 requires the two-sided corpus validation and the merge validation. Their results go into a dated section of [VALIDATION.md](../VALIDATION.md), with every flagged file reviewed. The relationship benchmark runs with the `no-new-wrong-pairs` gate and is recorded. It becomes a release gate once [relationships/07](../specs/relationships/07-relationship-validation.md) is accepted.
- A manual check of the built plugin on IC 2025.1.3 and IU 2026.3 covers the two-sided outline, the merge outline, the Changes tree rows with the filter and caret follow, and double-click and Enter on summarized and plain rows. A check that a probe ran without the real click or key path is recorded as inconclusive, not as a pass. The [manual runIde checklist](0.3.0-manual-check.md) records the 2026-11-08 run, when **R7 and R8 failed**, and the 2026-11-09 release-head re-check that passes both. Do not merge `main`, which carries #132 as 0.4.0 work. The remaining manual rows are listed there; #108 is verified and accepted, and #111 stays partial.
- `pluginVersion=0.3.0` and the CHANGELOG section is dated; the ROADMAP lists 0.3.0 as prepared, not published. The maintainer publishes the `v0.3.0` GitHub release only after the remaining manual rows in [0.3.0-manual-check.md](0.3.0-manual-check.md) are recorded; R7/R8 pass on `f912d8c` and #108 is verified.
