# 0.4.0 release plan

Status: planned, 2026-11-07. A proposal, not a commitment; [ROADMAP.md](../ROADMAP.md) stays the source for what has shipped.

**Theme:** structural relationships. 0.4.0 finishes the [structural relationships](../ROADMAP.md#after-020-structural-relationships) track: a rename is read once with its usages, an inlined helper is linked to the code it went into, and the outline can list a file's refactorings before its other changes. The release passes the relationship gates of [relationships/07](../specs/relationships/07-relationship-validation.md).

## Release checks

These are relationships/07 R1 to R12:

- The benchmark runs on all cases and real commits. High-confidence relationships reach at least 95% held-out precision for every kind and language, no ambiguous case is forced into a pair, and the `no-new-wrong-pairs` gate passes against the recorded baseline, with usages and inlinings included.
- The two-sided corpus validation has no new wrong link or hidden change compared with 0.3.0, and the merge validation has no new `join-mismatch` file.
- Every analyzed file passes the nothing-hidden check. Median and slowest times per language stay within the analysis limits with the reference pass on (`LimitsBenchmarkTest`).
- The golden fixtures and the engine contract suite pass. Plugin Verifier passes on both target IDEs with the Scala plugin, and every internal or experimental API use, including the Kotlin and Scala resolvers', is reviewed.
- Every wrong relationship found is fixed or listed as a known issue. The results are in a dated section of [VALIDATION.md](../VALIDATION.md) with the engine version, the reference pass version, the IDE builds, the Scala plugin version and the corpus revision.
- A manual check covers one rename with usages, one extraction and one inlining in each language, in both outline views.
- The release follows [RELEASING.md](../RELEASING.md).

**Usability study.** outline/06 is proposed and needs at least 5 participants. Its result is recorded in VALIDATION.md when it is available. It is not a 0.4.0 gate unless the maintainer decides it is, but no release text may claim that the outline makes reviews faster until the study passes outline/06 R7.

## Not in 0.4.0

- Relationships across files. The product scope would have to be extended first.
- The refactorings view in the merge outline and the Changes tree (relationships/06, out of scope).
- Moves inside declarations, fine-grained differencing and the other [Later](../ROADMAP.md#later) items.

## Rules for every task

- Read [AGENTS.md](../../AGENTS.md) and [SPEC-GUIDE.md](../SPEC-GUIDE.md) first. The spec wins over the code until the spec is changed, and tests name the requirement they check.
- Branch names have a type prefix and say what the change is. Session-generated names are not allowed.
- Every CI workflow step (`./gradlew clean buildPlugin check`, `./gradlew verifyPlugin`) passes locally before every push. The cloud sandbox blocks JetBrains downloads, so these run on the maintainer's computer through Remote Control, in a separate git worktree. Nothing is pushed untested in the hope that CI catches it.
- No new internal, experimental or deprecated API use, except usages a spec reviews and accepts.
- People are never named in repository content, commit messages or pull requests.
- A probe that bypasses the real action, click or key path is recorded as inconclusive, never as a pass.
