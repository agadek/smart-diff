# Go

Status: implemented, 2026-11-24

**Description:** The [declaration engine](../../GLOSSARY.md#declaration-engine) supports Go files, through the JetBrains Go plugin's parser, when the IDE has the Go plugin.

**Use case:** A developer reviews a Go change in GoLand, or in IntelliJ IDEA Ultimate with the Go plugin, and sees which functions, methods, types, fields, constants and variables changed, without reading every changed line.

## Requirements

- **R1** Go support works when the IDE has the Go plugin, and the plugin loads without it.
- **R2** `.go` files are a [supported language](../../GLOSSARY.md#supported-language) when the Go plugin is present.
- **R3** Top-level functions, methods, types, constants and variables are [declarations](../../GLOSSARY.md#declaration).
- **R4** A method is a top-level declaration shown as `Type.Name`, where `Type` is its receiver's type without `*` and type parameters.
- **R5** A type is a struct, an interface, a type alias or a defined type, by how it is written.
- **R6** A struct's fields, embedded fields included, and an interface's methods are declarations, and members of their type.
- **R7** Each spec of a grouped `type`, `const` or `var` declaration is its own declaration.
- **R8** Names declared together in one field, constant or variable spec, such as `X, Y int`, are one declaration named `X, Y`.
- **R9** Declarations inside a function body, function literals, the package clause, imports, and declarations named only `_` are not declarations.
- **R10** A declaration's range includes the comment lines directly above it.
- **R11** A function's [signature](../../GLOSSARY.md#signature) is its parameter types, without names, type parameters and results; a method's signature also names its receiver's type.
- **R12** Two functions named `init` in one file are separate declarations.
- **R13** Spaces and indentation are [formatting-only](../../GLOSSARY.md#formatting-only) when nothing else changed.
- **R14** An added or removed line break is a change.
- **R15** Extraction detection, inlining detection, rename candidates, kind changes and moves inside declarations work for Go as for the other languages.
- **R16** The merge outline and the Changes tree show Go files as they show Java files.
- **R17** Go has golden fixtures, merge fixtures and relationship benchmark fixtures, as the other languages do.

## Out of scope

- Grouping renames with their usages; S13 showed that in-file references resolve without a Go SDK, so a `GoReferenceResolver` is its own change to [relationships/04](../relationships/04-rename-grouping.md).
- Methods listed under their receiver's type; a method and its type are often in different files.
- Build constraints (`//go:build`), cgo preambles and generated code being told apart; they are content.
- Go module files (`go.mod`, `go.work`) and templates.
