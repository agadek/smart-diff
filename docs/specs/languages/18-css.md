# CSS, SCSS and Less

Status: implemented, 2026-11-24

**Description:** The [declaration engine](../../GLOSSARY.md#declaration-engine) supports CSS, SCSS and Less files, through the JetBrains CSS plugin's parser and its Sass and Less dialects, when the IDE has the CSS plugin.

**Use case:** A developer reviews a stylesheet change in WebStorm, IntelliJ IDEA Ultimate or another paid IDE and sees which [rule sets](../../GLOSSARY.md#rule-set), media queries, custom properties, variables and mixins changed, without reading every changed line.

## Requirements

- **R1** CSS support works when the IDE has the CSS plugin, and the plugin loads without it.
- **R2** `.css` files are a [supported language](../../GLOSSARY.md#supported-language) when the CSS plugin is present, `.scss` files when the Sass plugin is present and `.less` files when the Less plugin is present.
- **R3** A rule set is a [declaration](../../GLOSSARY.md#declaration) of [kind](../../GLOSSARY.md#kind) `rule`, named by its selectors.
- **R4** A rule set's name has one space for a descendant combinator, one space on each side of `>`, `+` and `~`, `, ` between selectors, and no other whitespace.
- **R5** An at-rule with a block, such as `@media`, `@supports`, `@layer`, `@container`, `@keyframes`, `@font-face` and `@page`, is a declaration of kind `at-rule`, named by its keyword and prelude.
- **R6** The rule sets, at-rules, custom properties and variables in a rule set's or an at-rule's block are its members, nested SCSS and Less rule sets included.
- **R7** A custom property, such as `--brand`, is a declaration of kind `variable` named `--brand`.
- **R8** In SCSS, `$name` variables, `@mixin`s and `@function`s are declarations, and a `%placeholder` rule set is a rule.
- **R9** In Less, `@name` variables, detached rule sets and mixins written with parentheses, such as `.border(@width)`, are declarations.
- **R10** A mixin is of kind `mixin`, and an SCSS function of kind `function`; the [signature](../../GLOSSARY.md#signature) of both is their parameter names, without default values.
- **R11** Ordinary properties, imports (`@import`, `@use`, `@forward`), `@charset`, `@namespace`, at-rules without a block, mixin calls, `@extend` and control directives (`@if`, `@each`, `@for`, `@while`) are not declarations.
- **R12** Nothing inside a mixin or an SCSS function is a declaration.
- **R13** A declaration's range includes the comment lines directly above it.
- **R14** Spaces, indentation and line breaks are [formatting-only](../../GLOSSARY.md#formatting-only) when nothing else changed.
- **R15** Whitespace that is a descendant combinator, or that is next to a `+` or `-` operator outside a selector, is a change when it is added, removed or changed.
- **R16** A rule set whose selector changed while its content stayed similar is a [rename candidate](../../GLOSSARY.md#rename-candidate).
- **R17** A Less rule set turned into a mixin of the same name, or back, is a [kind change](../../GLOSSARY.md#kind-change).
- **R18** Extraction detection, inlining detection, rename candidates and moves inside declarations work for CSS, SCSS and Less as for the other languages.
- **R19** The merge outline and the Changes tree show CSS, SCSS and Less files as they show Java files.
- **R20** CSS, SCSS and Less have golden fixtures and merge fixtures.

## Out of scope

- The indented Sass syntax (`.sass`), PostCSS, Stylus and CSS written inside HTML or JavaScript.
- Grouping a renamed selector with its usages in HTML, templates or other stylesheets.
- Declarations inside SCSS control directives, such as rule sets generated by `@each`; they are content of their container.
- A relationship benchmark corpus and a corpus validation for stylesheets; they can follow once the provider has users.
